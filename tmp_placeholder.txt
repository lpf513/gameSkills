# Game Design Document (GDD) Skill

## Philosophy

A GDD is the single source of truth for the entire development team. It translates a creative spark into an executable blueprint. Every paragraph must answer "what does the team need to know to build this correctly?"

## Document Architecture

When generating a GDD, follow this tiered structure. Scale depth based on project scope (indie ~5–15 pages AAA ~30–80 pages) but always preserve the logical hierarchy.

### 1. Executive Summary

- **Elevator Pitch**: One paragraph that captures genre target audience platform and unique selling point.
- **Pillars**: Exactly 3 design pillars. Each pillar is a single memorable phrase (e.g. "Kinetic Flow" "Emergent Storytelling" "Mastery Over Grind") followed by 2–3 sentences explaining what it means concretely.
- **Elevator Pitch Comparison**: Name 2–3 commercially successful touchstone titles and spell out how this game is both similar to and deliberately different from each.
- **Target Audience**: Primary and secondary personas with demographic psychographic and behavioral notes (session length platform preference monetization tolerance).

### 2. Game Overview

| Building Block | Description |
|---|---|
| **Genre** | Hybrid or pure genre classification with justification |
| **Platform & Engine** | Target platforms technical stack if known |
| **Art Style & Perspective** | Camera perspective visual reference tone/mood keywords |
| **Content & Scope** | Estimated playtime level count feature count "
